# KDP出版作業の代行可否と省力化の調査結果

- 調査日: 2026-08-07
- 目的: 著者から「KDPでの出版作業を代行してほしい。できないなら作業を極力減らす方法を調べてほしい」との要望

## 結論: 出版操作の代行はできない

理由は3つ。いずれも回避すべきでない性質のもの。

1. **公式APIが存在しない**
   KDPには、第三者システムから書籍の登録・アップロード・出版を行える公開APIがない。
   Amazon SP-APIは出品者(物販)向けであり、KDPの電子書籍出版フローは対象外。
   検索範囲では、KDP出版を自動化する公式手段は確認できなかった。

2. **ブラウザ自動操作による代行は規約上のリスクが高い**
   Amazonは各サービスの利用規約で自動化アクセス・スクレイピングを制限している。
   アカウントへのログインを伴う自動操作は、アカウント停止のリスクを著者に負わせる。
   出版アカウントは収益の受け取り口でもあるため、このリスクは取るべきでない。

3. **AIコンテンツ申告は名義人本人の申告行為**
   KDPは新規出版・改訂のたびにAI生成コンテンツ(テキスト・画像・翻訳)の申告を求めている。
   これはアカウント名義人が行う申告であり、代行にはなじまない。

## 代わりに実施した省力化(編集部側で完了済み)

| 施策 | 効果 |
|------|------|
| KDP入稿シートの作成(books/book02/kdp-input-sheet.md) | 全入力項目の値を画面順に確定。コピペのみで入力完了 |
| 商品説明文の完成版を用意 | 執筆・推敲の手間ゼロ |
| キーワード7個・カテゴリ候補の確定 | 選定作業ゼロ |
| EPUB生成(book02.epub) | 原稿変換作業ゼロ。Kindle Createでの編集も不要 |
| 表紙の完成(1600×2560px) | デザイン作業ゼロ |
| 法令記述のクロス検証(facts-kasuhara-verification-20260807.md) | 著者による原文確認作業が不要に |
| シリーズ名を表紙表記と一致させる修正 | 審査での差し戻しリスクを事前に排除 |
| book01改訂版EPUBの生成 | 相互送客の改訂作業がアップロードのみに |

著者に残る作業は「KDP画面でのコピペ入力とファイルのアップロード」のみ(15〜20分程度)。

## KDPの仕様で押さえておくべき点(調査で判明)

- **シリーズ機能**: シリーズ名にはフリガナ(カタカナ)の入力が必要。入力するシリーズ名と番号は、
  表紙・本文ファイルに含まれる表記と正確に一致する必要がある。
  → 本プロジェクトでは表紙の文言を「現場で使えるシリーズ 第2弾」に統一済み。
- **下書き保存**: 各ステップで下書き保存が可能。一度に終わらせる必要はない。
- **同時作成タイトル数の上限**: 1週間に同時作成できるタイトルは電子書籍・紙書籍それぞれ10点まで
  (本プロジェクトのペースでは問題にならない)。
- **原稿の差し替え**: 出版後もEPUBの再アップロードが可能。商品ページ・レビューは維持される。
- **AI申告**: 新規出版時だけでなく、既刊を編集して再出版する場合にも申告が必要。
  → book01の改訂時も、AI生成の申告内容(テキスト・画像とも「AI生成」)は変更なしで維持する。

## 今後さらに省力化できる余地

- 3冊目以降も同じ形式(入稿シート+EPUB+表紙)で用意すれば、1冊あたりの著者作業は15〜20分に固定できる。
- Amazon著者ページ(Author Central)への登録は初回のみ。2冊目以降は自動で著者ページに並ぶ。
