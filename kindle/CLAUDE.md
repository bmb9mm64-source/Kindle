# Kindle出版 編集部 — プロジェクト方針

このディレクトリは、AIを活用した実用書のKindle（Amazon KDP）継続出版プロジェクトの拠点です。
Claudeは「編集部スタッフ」として、企画（planner）・執筆補助（writer）・校正/申告チェック（editor）の
役割分担で作業します。オーナー（著者）は日本在住・出版経験ゼロ・週の作業時間限定。

## 目標

- 半年間で実用書を継続出版し、副収入を積み上げる。
- 品質と規約遵守を最優先とし、量産よりも「読者の課題を解決する本」を作る。
- 誇大な「稼げる」系の表現は使わない。主張には一次情報（Amazon/KDP公式ヘルプ等）を優先して当たる。

## KDPのAIコンテンツ申告ルール（毎回判定・厳守）

KDPは出版時に「AI生成コンテンツ」の申告を求めている。判定基準は以下の通り。

| 区分 | 定義 | 申告 |
|------|------|------|
| AI生成（AI-generated） | 本文・画像・翻訳をAIツールが「作成」した場合。人間が後から大幅に編集しても「AI生成」のまま | **必要** |
| AIアシスト（AI-assisted） | 人間が自分で作成したコンテンツを、AIで編集・校正・リファイン・アイデア出しに使った場合 | 不要 |

本プロジェクトの原則：

1. **オーナーが骨子（章立て・主張・実体験・具体例）を作る**。AIは編集・リライト・構成提案の補助に徹する。
2. ただし、AIが章の本文を実質的に「生成」した場合（writerのたたき台をほぼそのまま採用した場合を含む）は
   **正直に「AI生成」として申告する**。グレーな場合は申告する側に倒す。
3. **各書籍の出版前に、editorエージェントが「AI生成 / AIアシスト」のどちらに該当するかを必ず明示し、
   判定根拠を books/bookXX/ 内に記録する**（例：books/book01/ai-declaration.md）。
4. 表紙画像をAIで生成した場合も申告対象。画像の生成手段も毎回記録する。

## 価格・ロイヤリティ方針（日本）

- 販売価格：**250〜1,250円**（税抜）。この範囲がKDPの70%ロイヤリティ対象価格帯。
- **KDPセレクトに登録**し、70%ロイヤリティを選択する（70%はKDPセレクト登録が条件。日本のAmazon.co.jpでの販売）。
- 70%ロイヤリティでは配信コスト（ファイルサイズ×単価）が差し引かれるため、画像は必要最小限に圧縮する。
- 初期は低め（250〜500円）で参入し、レビューが付いたら見直す。

## 出版ペース制限

- **1日の出版数上限は3冊**（KDPの規約上の上限。これを超えない）。
- 実運用ではペースよりも品質を優先。週1冊前後を目安とし、無理な量産はしない。

## ターゲットジャンル方針

- **実用書（ノウハウ・ハウツー・体験談ベース）**に絞る。小説・絵本は当面扱わない。
- オーナーが「500文字以上、自分の言葉で語れる」実体験・専門知識のあるテーマのみ企画化する。
- 狙い目の判定：Amazon検索上位30冊にレビュー10件未満の本が複数入っているジャンル＝競合が弱く参入余地あり。
  逆に上位が全てレビュー100件超なら避ける（詳細は .claude/agents/planner.md）。
- 医療・法律・投資など、誤情報が読者に実害を与えうるYMYLテーマは、オーナーに資格・実務経験がない限り扱わない。

## 表紙仕様

- サイズ：**1600×2560px**（縦横比 1:1.6、KDP推奨サイズ）。
- 形式：JPEG または TIFF、RGB、72dpi以上。ファイルサイズは50MB未満。
- 表紙をAI生成した場合は申告対象（上記ルール参照）。

## 作業の進め方

1. **企画**：オーナーの実体験テーマを起点に、planner が競合リサーチ（/research）→ テーマ・タイトル案を提示。
2. **骨子作成**：オーナーが章立て・各章の主張・実体験・具体例をメモで用意する（ここが「人間の著作」の核）。
3. **執筆**：writer が骨子から章ごとのたたき台を作成 → オーナーがリライト・加筆して自分の文章にする。
4. **校正**：editor が誤字脱字・読みやすさをチェックし、AI生成/アシスト判定を明示する。
5. **出版前チェック**：/publish-check でタイトル・表紙・価格・KDPセレクト・AI申告・カテゴリ/キーワードを最終確認。
6. **記録**：各書籍のフォルダ（books/book01/ など）に企画メモ・原稿・申告判定・出版情報を残す。

## 確立した制作パイプライン（1・2冊目で運用実績あり）

1冊あたり、著者の作業は**KDP画面での入力15〜20分のみ**に圧縮できている。編集部側の標準手順:

1. **企画**: planner が競合リサーチ（/research）→ 企画書 plan.md + 骨子 outline.md
2. **執筆前リサーチ**: 事実に依拠する章がある場合は先に事実パックを作る（knowledge/facts-*.md）。
   本文はそのパックの確認済み事実だけで書く
3. **執筆**: writer を3並列（例: 1〜3章 / 4〜5章 / 6〜7章）で走らせる。
   並列執筆は章間で表記・章題・重複がぶれるため、**editorでの統一を必ず入れる**
4. **前付け・後付け**: 「はじめに」「おわりに」を作成。AI活用と申告の旨を読者向けに明記し、
   巻末にシリーズ他書の紹介（相互送客）を入れる
5. **校正・申告判定**: editor が校正（機械的な修正は直接適用、判断要は指摘リスト）と
   AI生成/アシスト判定 → ai-declaration.md
6. **事実の再検証**: 法令等を扱った場合、独立した複数ソースでクロス検証し検証結果を残す
   （著者の確認作業をゼロにするため）
7. **原稿結合・EPUB化**: manuscript.md に結合 → pandoc で EPUB 生成（表紙・目次同梱）
   ```
   pandoc 原稿.md -o bookNN.epub --metadata title="..." --metadata lang=ja \
     --epub-cover-image=cover-1600x2560.jpg --toc --toc-depth=1 --split-level=1
   ```
8. **出版前チェック**: /publish-check → publish-check-YYYYMMDD.md
9. **入稿シート作成**: kdp-input-sheet.md に全入力値を画面順で確定（著者はコピペのみ）
10. **記録**: publication-record.md に出版日・ASIN・改訂履歴

## シリーズ運用（「現場で使えるシリーズ」）

- タイトルの型: 『営業・接客の現場で使える〇〇術 ― サブタイトル』
- **KDPのシリーズ名は表紙の表記と正確に一致させる**（不一致は審査で差し戻しリスク）。
  現行のシリーズ名: `現場で使えるシリーズ` / フリガナ: `ゲンバデツカエルシリーズ`
- 表紙は同一レイアウトの配色違い（1冊目=紺、2冊目=深紅）。下部の黄色帯は共通のシリーズ記号
- 価格は480円で統一（シリーズ買いしやすさ優先）
- 相互送客: 各巻の巻末に他巻の紹介、商品説明文の末尾にシリーズ案内、同一ペンネームで著者ページに集約
- 1冊1テーマ（読者の悩みを1つ解決）を守り、巻ごとの守備範囲を企画書に明記して重複を避ける

## KDPに関する運用知識（調査済み・knowledge/kdp-publishing-notes-*.md）

- **出版操作を代行できる公式APIは存在しない**。ブラウザ自動操作での代行は規約リスクが高く行わない。
  AI申告はアカウント名義人本人の申告行為である
- 出版後もEPUBの再アップロードで原稿を差し替え可能（商品ページ・レビューは維持）。
  ただし**既刊を編集して再出版する場合もAI申告が必要**
- 各ステップで下書き保存が可能。1週間に同時作成できるタイトルは各フォーマット10点まで
- 政府・自治体ドメインはこの作業環境からアクセス不可（EGRESS_BLOCKED）。
  法令の確認は「アクセス可能な独立複数ソースでのクロス検証」で代替する

## ディレクトリ構成

```
kindle/
├── CLAUDE.md            # 本ファイル（プロジェクト方針・運用ルール）
├── books/
│   ├── book01/          # 1冊目（出版済み）
│   ├── book02/          # 2冊目（出版準備完了）
│   └── bookNN/          # 各巻: plan.md / outline.md / draft/ / manuscript.md /
│                        #        bookNN.epub / cover-1600x2560.jpg /
│                        #        proofreading-report.md / ai-declaration.md /
│                        #        publish-check-*.md / kdp-input-sheet.md /
│                        #        publication-record.md
├── knowledge/           # 競合リサーチ・事実パック・KDP運用知識の蓄積
└── .claude/
    ├── agents/          # planner / writer / editor サブエージェント定義
    └── commands/        # /research /publish-check スラッシュコマンド
```

## 禁止事項

- 「必ず稼げる」「不労所得」等の誇大表現をタイトル・説明文・原稿に使うこと。
- 他書のコピー・剽窃、レビューの自作自演、規約違反となるキーワード詰め込み。
- AI申告の虚偽（AI生成なのに未申告で出版する等）。判断に迷ったら申告する。
